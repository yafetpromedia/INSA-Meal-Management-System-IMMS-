# SOFTWARE REQUIREMENTS SPECIFICATION (SRS)

# Part 2 — Functional Requirements (Meal Management)

## 2.1 Overview

IMMS provides meal distribution management across organizations, campuses, programs, and academic years.

Core modules:

1. Authentication
2. Dashboard
3. Campus Management
4. Program Management
5. Academic Year Management
6. Student Management
7. Excel Import
8. Barcode Scanner / Verification
9. Meal Sessions
10. Meal Distribution
11. Meal History
12. Mentor Management
13. Food Staff Management
14. Reports
15. Audit Logs
16. Settings
17. User & Role Management

## 2.2 Authentication

Email/password login; access + refresh tokens; Argon2 password hashing; account lockout; session logout current/all; forgot-password with expiring token.

## 2.3 Dashboard

Role-personalized meal stats: total students, meals served today by session, duplicate scan attempts, active mentors/food staff, current meal session, live meal activity feed.

## 2.4–2.6 Organization structure

Unlimited organizations, campuses, programs, and academic years — all configurable; no hard-coded institution.

## 2.7 Students

Imported from Excel. Student ID is never generated by the system; barcode = Student ID.

## 2.8 Excel Import

Validate → preview → duplicates/errors → confirm. Modes: Add Only, Update Existing, Replace Existing. Import history retained.

## 2.9–2.11 Meals

Configurable sessions (Breakfast/Lunch/Dinner by default). Auto-detect current session from time windows. One meal per session per day; admin override with reason + audit. Full meal history per student.

## 2.12 Staff

Mentors and Food Staff managed as users with RBAC and campus/program assignments.

## 2.13–2.17 Cross-cutting

Notifications, search/filter/pagination, realtime meal updates, friendly errors, performance targets for scan/serve under 2 seconds.
